# CANE DO 협업 전체 지침 (초안 v0.1)

> 정은과 대화하며 계속 채워 가는 문서입니다. `[정해야 함]` 표시는 아직 정해지지 않은 부분이에요.

## 1. 목적
10월 15일 흰지팡이의 날, 초등학생이 시각장애 이해와 배려 방법을 게임으로 익힌다. 모든 판단 기준은 "흰지팡이의 날 수업에 쓸 수 있는가".
기획 원문: `docs/기존자료/기획서_v5.md` (충돌하면 이 지침과 정은의 결정이 우선) `[정해야 함: 새 게임 구성 반영]`

## 2. 화면 순서
오프닝 → [ 단계 로딩 → 게임 N → 브리지 ] × 게임 수 → 마지막 화면 → 랭킹
게임은 현재 4개이며 늘어날 수 있다. `src/parts/game-5/` 처럼 폴더만 추가하면 자동 연결된다.

| 파트 | 폴더 | 담당 | 내용 |
|---|---|---|---|
| 오프닝 | opening | 정은 | START, 별명·소속 입력 |
| 단계 로딩 | stage-loading | 정은 | 각 단계 시작 전 로딩 |
| 게임 1 | game-1 | `[담당자]` | OX 퀴즈 |
| 게임 2 | game-2 | `[담당자]` | 반찬 + 길 안내 (변경될 수 있음) |
| 게임 3 | game-3 | `[담당자]` | 점자 관련 퀴즈 + 자모음자 점자 입력 |
| 게임 4 | game-4 | `[담당자]` | 점자 암호 해독 |
| 브리지 | bridge | 정은 | 게임 결과 피드백 |
| 마지막 화면 | ending | 정은 | 마무리 |
| 랭킹 | ranking | 정은 | 전체 / 소속별 / 소속 안 랭킹 |

## 3. 파트 약속 (가장 중요)
모든 파트는 아래 모양의 React 컴포넌트를 `index.jsx` 에서 `export default` 한다.

| 파트 | 받는 props | 끝날 때 |
|---|---|---|
| 게임 | `stage` `{index,total,title,folder}`, `player` `{name,group}` | `onFinish({ score, mistakes, hints, timeMs })` 를 **한 번** 호출 |
| 단계 로딩 | `stage` | `onDone()` |
| 브리지 | `stage`, `result`(방금 게임 결과), `results`(지금까지 전체) | `onNext()` |
| 마지막 화면 | `player`, `results` | `onNext()` |
| 랭킹 | `player`, `results` | `onRestart()` |
| 오프닝 | 없음 | `onStart({ name, group })` |

- `score`: 0~100 정수 (게임 안에서 계산). 높을수록 좋음.
- `mistakes`: 틀린 횟수, `hints`: 쓴 힌트 수, `timeMs`: 걸린 시간(ms)
- 각 폴더에는 `manifest.js`(이름·순서·담당)와 `index.jsx` 가 반드시 있어야 한다.

## 4. 폴더 규칙
- **내 폴더 안에서만** 파일을 만들고 고친다. `shared/`, `flow/`, 다른 파트는 수정 금지 (CODEOWNERS 로 막힘).
- 공통 부품은 `import { Window, Button, QuizWindow, useT, braille } from '../../shared'` 로만 가져온다.
- 필요한 그림·소리·기능이 없으면 직접 만들지 말고 **"에셋 요청" 이슈**를 올린다. 정은이 라운드 사이에 추가한다.
- 게임 안에서만 쓰는 이미지는 내 폴더의 `assets/` 에 둔다.
- 다른 파트 폴더를 import 하지 않는다.

## 5. 공통 규칙 (기존 앱에서 유지)
1. 기준 화면 1280×720 가로. `Stage` 가 비율 확대·축소를 처리하므로 파트는 1280×720 안에서만 배치한다.
2. 하단 저작권 표시와 전체 틀은 `Stage` 가 넣는다. 파트에서 따로 넣지 않는다.
3. 모든 글은 **쉬운 글 / 기본 글** 두 가지. 문자열 대신 `{ basic: '…', easy: '…' }` 로 쓰고 `useT()` 로 표시한다.
4. 퀴즈 문제·보기·정답·해설·힌트는 `docs/기존자료/퀴즈_해설_검토본.md` 를 **한 글자도 바꾸지 않고** 사용한다.
5. 그림은 코드로 그린 도트(픽셀) 또는 디자인에서 받은 에셋만. 기존 게임의 캐릭터·에셋 사용 금지. `image-rendering: pixelated`.
6. 흰지팡이는 빨간 줄 없는 순수한 흰색.
7. 시각장애인을 불쌍하거나 우스꽝스럽게 표현하지 않는다. 학생은 늘 "도와주는 친구". "불쌍한", "극복", "장애를 체험" 금지.
8. 시야 효과를 쓸 때는 설명 카드를 먼저 보여 주고, 깜빡임·오래 깜깜한 화면 금지.
9. 키보드로도 조작되게 하고 포커스 표시를 지운다. 색에만 의존하지 않는다.
10. 저장이 필요하면 localStorage (try/catch 로 감싸기). 서버 연결은 랭킹 파트만.
11. 겹받침은 점자 변환 시 "이 글자는 준비 중이에요" 로 표시.
12. 개인정보: 실명 받지 않기. 별명과 소속만 사용.

## 6. 작업 방식 (라운드)
1. **1차 제작** (기한 `[정해야 함]`): `round1/game-N` 브랜치에서 작업 → PR
2. **피드백**: 정은이 PR 댓글로 요청. 같은 브랜치에 커밋으로 반영.
3. **합치기**: 정은이 병합하고 태그 `round-1`.
4. **에셋 조정**: 정은이 `shared/` 수정 (이 기간엔 새 작업 시작 X). 변경 내용은 `docs/shared_변경기록.md`.
5. **2차 제작** (기한 `[정해야 함]`): 최신 `main` 을 받아 `round2/game-N` 에서 시작.
- PR 마다 Vercel 미리보기 주소가 만들어진다. 피드백은 그 주소로 직접 해 보고 한다.
- 커밋 메시지는 한국어로 짧게. 예: `game-1: 정답 표시 추가`
